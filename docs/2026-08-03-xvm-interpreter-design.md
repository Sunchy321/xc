# X 解释器垂直切片设计

日期：2026-08-03
仓库：`xc`

## 背景

设计方向经多轮讨论收敛如下：

- **产品形态（参考 bun）**：一个能直接运行 `.x` 文件与 REPL 的运行时，无独立构建步骤，启动开销小，GC 管引用。
- **引擎（参考 JSC）**：字节码 + 解释器主循环 +（未来）JIT。借鉴其分层和演化路径——从纯字节码解释器起步。
- **编译管线（参考 rustc）**：前端分层，先有稳定的中间表示，再做后端。
- **类型系统（TS 式）**：结构化、宽松、渐进；类型在运行时擦除。**移动语义 + `Copy` 是纯编译期检查**，阻止 use-after-move，与运行时动态类型不冲突——两条轴正交。
- **值表示**：宽松 tagged 值，对象装箱，不追求紧凑二进制布局。
- **策略**：垂直切片优先——先打通一条最小链路，再横向扩特性。

## 目标

第一个里程碑：`x run foo.x` 端到端执行 X 语言最小子集，链路为

```
解析 → 检查 → 字节码 → 栈式 VM
```

价值在于跑通完整链路，为后续横向扩展建立骨架。

## 非目标（切片明确不做）

- 数组、异常（try/catch）、闭包、对象/class/trait/impl、运算符重载、`&T` 句柄
- 类型检查器（仅做名字解析与参数个数等最小检查）
- 真 GC（值由 VM 直接持有；GC 留到 `&T` 引用与循环出现后）
- REPL 迁移到 VM（`xepl` 保持不变，除共用 `xvalue` 的机械改动）
- JIT 与优化

## 架构

```
foo.x
  → xc_lexer / xc_parse / xc_ast   （现有，不动）
  → xc_check（新）                 名字解析 + 符号表 + 最小检查
  → xvm（新）                      AST → 字节码 → 栈式 VM 执行
  → x 二进制（根包改名）            CLI：x run foo.x
```

| 组件 | 职责 |
|------|------|
| `xc_check` | 编译期分析。收集顶层函数与变量 → 符号表；检查未定义函数/变量、参数个数、重复定义 |
| `xvm` | 引擎。字节码 IR（Chunk/指令）、AST→字节码编译器、栈式 VM、内建函数 |
| `xvalue` | 运行时值表示。从 `xepl` 抽离的 tagged `Value` 枚举，`xepl` 与 `xvm` 共用 |
| `x`（根包） | CLI 驱动：parse → check → compile → run |

## 命名约定

- `xc_*`：编译期/前端工作（`xc_ast`、`xc_parse`、`xc_check`）
- `x*`：运行期/引擎工作（`xepl`、`xvalue`、`xvm`）
- 二进制：`x`

根包由 `xc` 改名为 `x`，产出 `x` 二进制。`xc` 作为前缀仅指编译期工作，不作为二进制名。

## 字节码设计（`xvm` 内部）

栈式 VM。每个函数一个 `Chunk`，另有一个顶层 `Chunk`。`Chunk` = 指令数组 + 常量池 + 行号表。

指令草图（实现时以实际为准）：

- 常量/变量：`Const`、`LoadVar`、`StoreVar`、`Pop`
- 运算：`Add`、`Sub`、`Mul`、`Div`、`Mod`、`Neg`、`Eq`、`Ne`、`Lt`、`Gt`、`Le`、`Ge`、`Not`、`And`、`Or`
- 控制流：`Jmp`、`JmpIfFalse`
- 函数：`Call`、`Ret`
- 内建：`Print`

常量池：`Int`/`Bool`/`String`/`Nil`。

## VM 设计

- 值栈：`Vec<Value>`
- 调用帧栈：`{chunk, ip, 基址, 返回地址}`
- `Value`：`Void`/`Nil`/`Bool`/`Int`/`String`（切片范围），沿用现有 tagged 枚举，抽离到 `xvalue`
- 内建 `print`：注册为 VM 原生函数
- 函数调用按函数名查 chunk 表；顶层 `return` 结束程序（与现有树遍历行为一致）

## 错误处理

- 解析错误：复用 `xc_error` diagnostics
- 检查错误：报 `file:line`
- 运行时错误（除零、类型不匹配）：报出错位置 + 简单调用栈

## CLI

- `x run foo.x`：驱动执行
- 无参数/未知子命令：打印用法
- 后续：`x check`、`x repl`

## 数据流

解析 → 检查（符号表）→ 每函数编译成一个 `Chunk` + 顶层 `Chunk` → 顶层顺序执行。`Call` 按函数名查 chunk 表。

## 测试

- `.x` 金样本：输入文件 → 期望输出，跑在 `xvm` 上
- `xvm` 字节码编译器单测
- `xvm` VM 指令单测
- `xepl` 现有功能不回归

## 未来方向（记录，不实现）

- 分析层扩展：TS 式宽松类型检查器 + 移动语义/`Copy` 编译期检查
- 闭包：需要 upvalue / 环境链
- 异常：需要 unwinding 机制
- 真 GC：`&T` 引用、循环、弱引用
- 字节码优化 / JIT（寄存器式 VM 等）

## 已确认决策

- 引擎为栈式 VM（非寄存器式），匹配"先跑通、不追求紧凑"
- 值表示宽松，不追求紧凑二进制布局
- 移动语义 + `Copy` 为编译期检查，不参与运行时
- `xc_*` 前缀限编译期工作，运行期用 `x*` 家族
